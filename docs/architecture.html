1. Executive Summary & Overview

CodeScout is a production-grade autonomous AI coding agent designed to interact with real-world GitHub codebases. Rather than acting as a standard LLM chat completion wrapper, CodeScout combines:

  • Tree-sitter AST Syntax Parsing: Deep semantic understanding that respects language boundaries, function declarations, class scopes, and docstrings.
  • Hybrid Search (Vector + Ripgrep RRF) & Reranking: Combines 2048-dim vector embeddings with exact identifier keyword search, fused via Reciprocal Rank Fusion ($k=60$) and scored by a cross-encoder reranker (achieving 1.00 MRR).
  • Hand-Written Deterministic Agent Loop: Direct control over retries, error recovery, step limits, and real-time Server-Sent Events (SSE) streaming without framework bloat.
  • Defense-in-Depth Container Sandboxing: Ephemeral test execution containers with dropped Linux capabilities, read-only root filesystems, zero network access, and isolated Git worktree branching.
  • Automated Pull Request Lifecycle: GitHub App RS256 JWT signing, short-lived tokens, worktree branch push, and LLM-generated PR descriptions.

4. Core Engineering Workflows

4.1 Repository Ingestion & Tree-Sitter AST Chunking

When a repository is connected, it is cloned into /data/repos/{repoId}/base. The agent processes files through Tree-sitter language grammars rather than arbitrary token counts:

  • Identifies function, method, and class definitions as unified AST nodes.
  • Preserves parent context hierarchy (e.g. class AuthService > def verify_token).
  • Generates 2048-dimensional embeddings in batches of 16 using NVIDIA's nemotron-3.5-embed-1b model.
  • Stores chunks in MongoDB Atlas with a dedicated Vector Search index alongside exact file/line bounds.

4.2 "Ask" Mode: Grounded Q&A with Line-Level Citations

When a developer asks a question about the repository:

Hybrid Fusion & Rerank Formula:
Candidates are retrieved using both Vector Search (semantic similarity) and Ripgrep (exact keyword matches), combined via Reciprocal Rank Fusion (RRF, $k=60$):
RRF_Score(d) = (1 / (60 + rank_vector(d))) + (1 / (60 + rank_keyword(d)))
The top 30 candidates are passed to a cross-encoder model (nemotron-3.5-rerank-8b) to guarantee that the primary ground-truth file occupies Rank 1.

The agent answers with clickable citations (e.g., [src/auth.ts:25-60]). Clicking a citation immediately highlights the lines in the Monaco code viewer.

4.3 "Edit" Mode: Sandboxed Code Modification & Verification

1. Worktree Branching

Edits never touch the base repository. A new Git worktree is created at /data/repos/{repoId}/runs/{runId} on a branch named agent/{runId}.

2. Ephemeral Sandbox

An isolated container mounts the worktree. Capabilities are dropped (--cap-drop ALL), root is read-only, and network is disabled.

3. Safe Tool Execution

The agent executes edit_file (exact string replacement) and run_command (test runner) inside the sandbox, iterating up to 3 times on test failures.

4. Monaco Diff Review

Once tests pass, a Git diff is packaged. The frontend renders a Monaco DiffEditor displaying modifications and test output for human review.

4.4 Automated Pull Request Creation

When the user approves a changeset and clicks "Create Pull Request":

  1. The Node API signs a JWT with RS256 using your GitHub App's private key (github-app.pem).
  2. An installation access token is requested from GitHub on-the-fly (valid for 1 hour, never persisted).
  3. The agent sets a standardized git committer identity (CodeScout Agent <agent@codescout.dev>) and pushes branch agent/{runId} to GitHub.
  4. An LLM creates a structured markdown pull request description detailing the changes, test command, and exit status.
  5. The PR is opened against the default branch, and a live link is returned to the user.

5. Security, Hardening & Maintenance

  • Rate Limiting: Dual-layer rate limiting protects against abuse (120 requests/min per IP, 60 requests/min per user). Exceeding limits triggers an HTTP 429 response with Retry-After headers.
  • Public Demo Guard: EDIT_ALLOWLIST=Rahul1907 restricts Edit mode, diff approval, and PR creation strictly to authorized GitHub accounts. All other visitors are restricted to Ask mode.
  • Automated Disk Maintenance: The BullMQ worker runs hourly cleanup sweeps to purge worktree folders older than 24 hours and base clones unused for >14 days, preventing disk exhaustion and keeping the Oracle VM active.
  • System Health Monitoring: /api/status exposes real-time health, ping latencies, and availability for MongoDB, Redis, the Agent service, and NVIDIA LLM endpoints.
